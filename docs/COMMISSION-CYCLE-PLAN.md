# แผน: ป๊อปอัพ "ค่าคอมรอบตัด" (26 → 25) — รายคน + รายทีม

> **สถานะ: รอพี่ตรวจ+ยืนยันก่อนลงมือ** — ยังไม่แตะโค้ด
> โจทย์: ปกติค่าคอมตัดรอบ 26/7–25/8 แต่ระบบดูได้แค่เดือนต่อเดือน → อยากรู้ว่ารอบนี้ได้คอมเท่าไหร่
> แนวทางที่เลือก (ตามพี่สั่ง): **ไม่ขยับหน้า salePerf เดิม** — ทำ **popup แยก** เปิดจากหน้าประสิทธิภาพเซลล์

---

## 1. หน้าตา + การใช้งาน

**ปุ่มใหม่** บนหัวหน้า "ประสิทธิภาพเซลล์": `[ ค่าคอมรอบตัด ]` → เปิด SideSheet (popup ขวา แบบเดียวกับ popup อื่นทั้งแอป)

**ใน popup:**
```
ค่าคอมรอบตัด · รอบ ส.ค. 69          [◀ รอบก่อน]  [รอบถัดไป ▶]
26 ก.ค. 2569 – 25 ส.ค. 2569 (31 วัน · ผ่านมาแล้ว 19 วัน)
วันตัดรอบ: ทุกวันที่ 26 [แก้ได้เฉพาะแอดมิน]

┌─ สรุปทีม ────────────────────────────────┐
│ ยอดขายรวมในรอบ  ฿xxx,xxx                  │
│ ค่าคอมรวมทั้งทีม  ฿xx,xxx                 │
└──────────────────────────────────────────┘

รายคน (เรียงยอดมาก→น้อย)
┌──────────┬────────────┬──────────┬──────────┬─────────┐
│ เซลล์     │ ยอดในรอบ   │ เรทที่ใช้ │ ค่าคอม    │ vs รอบก่อน│
│ TUKTA    │ ฿61,510    │ 3%       │ ฿1,845   │ ▲ 12%   │
│ PAI      │ ฿49,144    │ tier 2%  │ ฿983     │ ▼ 5%    │
│ FAH      │ ฿24,734    │ ยังไม่ตั้ง │ —        │         │
└──────────┴────────────┴──────────┴──────────┴─────────┘
   ↑ คนที่ยังไม่ตั้งเป้า/เรทของเดือนนั้น = ขึ้น "ยังไม่ตั้ง" + ลิงก์ไปหน้าตั้งเป้า

[ดาวน์โหลด CSV]   ← สำหรับทำเงินเดือน (ถ้าพี่เอา — ดูคำถามท้าย)
```

- **เลื่อนดูรอบย้อนหลังได้** (◀ ▶) เช่น รอบ ก.ค. = 26 มิ.ย.–25 ก.ค.
- **สิทธิ์:** แอดมินเห็นทั้งทีม · เซลล์ธรรมดาเปิดได้แต่เห็นเฉพาะแถวตัวเอง (กติกาเดียวกับหน้า salePerf ปัจจุบัน)

## 2. นิยามรอบ + สูตร (ต้องตกลงกันชัดๆ — สำคัญสุดเพราะเป็นเงินจริง)

| เรื่อง | ข้อเสนอ (ค่า default ที่ผมแนะนำ) |
|---|---|
| **วันตัดรอบ** | ค่าเดียวทั้งทีม = **26** (ตั้งได้ 1–28 · ห้าม 29-31 กันเดือน ก.พ. พัง) · เก็บใน `tmk_settings` (ทีมเห็นตรงกันทุกเครื่อง) · แก้ได้เฉพาะแอดมิน |
| **ชื่อรอบ** | 26 ก.ค.–25 ส.ค. = **"รอบ ส.ค."** (เรียกตามเดือนที่จบ/เดือนที่จ่ายเงิน) — โชว์วันที่เต็มกำกับเสมอ ไม่ให้งง |
| **เรท/เทียร์ที่ใช้** | ใช้ **เป้า+เรทของเดือนที่จบรอบ** (รอบ ส.ค. → ใช้เรทที่ตั้งไว้เดือน ส.ค.) — ไม่ต้องตั้งเป้าใหม่ ใช้หน้าตั้งเป้าเดิมได้เลย |
| **ยอดที่ใช้คิดคอม** | ยอดขายของเซลล์ในช่วงรอบ = **สูตรเดียวกับหน้า salePerf เป๊ะ**: ตัดออเดอร์ยกเลิก · รวมการแก้ไข (override) แล้ว · ทุกช่องทางของเซลล์คนนั้น |
| **สูตรคอม** | ตัวเดียวกับที่ใช้อยู่ (`commissionFor`): tiers ขั้นบันไดถ้ามี ไม่งั้น flat % — **ไม่เขียนสูตรใหม่ ไม่มีทางเลขไม่ตรง** |
| **เทียบรอบก่อน** | โชว์ ▲▼% เทียบรอบตัดก่อนหน้า (26 มิ.ย.–25 ก.ค.) — ช่วงยาวพอๆ กัน เทียบได้จริง |

**ข้อสังเกตที่ต้องรู้ (edge case คิดไว้แล้ว):**
- รอบคร่อมปีใหม่ (26 ธ.ค.–25 ม.ค.) → คณิตวันที่รองรับ (มีเทสครอบ)
- ถ้าเดือนไหนแก้เรทกลางเดือน → ทั้งรอบใช้เรทของเดือนที่จบรอบ (convention เดียว ชัดเจน)
- tiers ขั้นบันไดตั้งไว้สำหรับ "ยอดต่อเดือน" — รอบตัดยาว ~1 เดือนเท่ากัน เทียบขั้นได้ตรงๆ

## 3. กระทบอะไรบ้าง (วิเคราะห์ครบแล้ว)

### ✅ ไม่กระทบเลย (จุดแข็งของแนวทาง popup แยก)
| ระบบ | เหตุผล |
|---|---|
| หน้า salePerf เดิม (ยอด/ออเดอร์/คนทัก/%ปิด/กราф/การ์ดเซลล์) | ยังเป็นเดือนปฏิทินเหมือนเดิม 100% — ไม่แตะ `buildPerf` เลย |
| รายงานขาย / ยอดเดือน / สรุปเดือน | ไม่เกี่ยวกับคอมเซลล์อยู่แล้ว |
| รายงาน LINE รายวัน (edge fn) | ไม่ใช้คอมเซลล์ |
| หน้าตั้งเป้า/คอม (TargetsView) | ใช้ต่อได้เลย ตั้งตาม YYYY-MM เหมือนเดิม |
| เป้า CRM (โทร/LINE) | **ไม่แตะ** — ยังเป็นเดือนปฏิทิน (ถ้าอยากให้ตามรอบด้วย ค่อยทำทีหลังได้) |
| ฐานข้อมูลเดิม | ไม่แก้ตารางไหน — เพิ่มคอลัมน์เดียวใน `tmk_settings` |

### ⚠️ สิ่งที่เพิ่ม/เปลี่ยน
| # | อะไร | รายละเอียด |
|---|---|---|
| 1 | **migration เล็ก 1 ไฟล์** | `alter table tmk_settings add column if not exists commission_cutoff_day int` (พี่รันเองใน SQL Editor ตามปกติ) · **FE ทน schema**: ถ้ายังไม่รัน → popup ใช้ค่า 26 ไปก่อน ไม่พัง |
| 2 | **lib ใหม่ `commissionCycle.js`** | คณิตรอบ (from/to/label/รอบก่อน) + รวมยอดต่อเซลล์ในรอบ — **แยกไฟล์ pure + เทสครอบทุกเคส** (คร่อมปี, ก.พ., ตัดยกเลิก, override) |
| 3 | **popup ใหม่ 1 ไฟล์** | `commissionCycleSheet.jsx` (lazy-load — ไม่ถ่วงหน้าเดิม) |
| 4 | **ปุ่ม 1 ปุ่ม** ใน salePerf header | จุดแตะไฟล์เดิมมีแค่นี้ (บรรทัดเดียว + import lazy) |

### 📊 การดึงข้อมูล (ไม่หนักขึ้น)
- popup เปิด → ดึงออเดอร์ช่วงรอบผ่าน `cachedFetchRange` (**ระบบ cache เดิม TTL 5 นาที** — ช่วงรอบคาบเกี่ยวกับที่หน้าโหลดอยู่แล้ว ส่วนใหญ่โดน cache) + เป้าเดือนจบรอบ + รอบก่อน (สำหรับ ▲▼)
- ขนาดข้อมูล ≈ 1 เดือน = เท่าที่หน้า salePerf โหลดปกติ → **egress ไม่บวม**

### ⚠️ จุดที่คนอาจงง (คิดวิธีกันไว้แล้ว)
- **จะมีเลขคอม 2 ที่**: การ์ดเซลล์ในหน้าเดิมโชว์ "คอมเดือนปฏิทิน" ส่วน popup โชว์ "คอมรอบตัด" → กันงงด้วย label ชัดๆ: การ์ดเดิมเติมคำว่า *(เดือนปฏิทิน)* · popup เขียน *"รอบตัดจริงที่ใช้จ่ายเงิน"* — **ตัวเลขจ่ายจริง = popup**
